# Free deployment guide — live site, no more running code manually

**Stack (all free tiers):** Frontend → **Vercel** · Backend → **Render** · Database + image storage → **Supabase**.
After this, updating products, uploading photos and managing enquiries all happen on the
live site (`/admin/...`) — no code runs needed. Total cost: ₹0.

**Free-tier limits to know:** Render free sleeps after ~15 min idle (first visit wakes it in
~50 s); Supabase free = 500 MB database + 1 GB storage (plenty for a catalogue);
Vercel free = generous for this traffic. Nothing here charges a card by surprise, but
read each platform's current limits before going live.

---

## Step 0 — Push this project to GitHub (5 min)

Vercel and Render deploy straight from Git. The project is already a committed git repo.

1. Create a **free GitHub account** (if needed) → New repository, e.g. `new-look-impex`
   (private is fine; do NOT make it public if you prefer).
2. In PowerShell, from the project folder:
   ```powershell
   git remote add origin https://github.com/<your-username>/new-look-impex.git
   git branch -M main
   git push -u origin main
   ```
   (GitHub will ask you to sign in — use the browser/device flow it shows.)
3. `.env` (passwords, secrets) and `*.db` files are git-ignored — they never leave your PC.

## Step 1 — Supabase: database + image storage (10 min)

1. Create a **free Supabase account** → New project → copy the **pooled connection string**
   (Project Settings → Database → Connection string, port 6543 pooler mode).
2. Convert it for our backend:
   `postgresql://...` → `postgresql+psycopg2://user:pass@host:6543/dbname`
   (just insert `+psycopg2` after `postgresql`).
3. Storage → New **public** bucket `nli-media` (so product images persist — Render's disk is
   temporary). Then Project Settings → API → **S3 Access Keys** → create a key pair, and note:
   - S3 endpoint: `https://<project-ref>.storage.supabase.co/storage/v1/s3`
   - Public URL: `https://<project-ref>.supabase.co/storage/v1/object/public/nli-media`

## Step 2 — Render: backend API (10 min)

1. Create a **free Render account** (GitHub sign-in is easiest) → **New → Blueprint** →
   connect your `new-look-impex` repo. `render.yaml` in the repo configures everything.
2. Fill the secrets Render asks for:
   - `DATABASE_URL` → your Supabase string from Step 1
   - `ADMIN_EMAIL` → your email · `ADMIN_PASSWORD` → a strong new password
   - `CORS_ORIGINS` → leave `http://localhost:3000` for now; you will add the Vercel URL in Step 4
   - `API_BASE_URL` → your Render URL, e.g. `https://new-look-impex-api.onrender.com`
   - `PUBLIC_SITE_URL` → your Vercel URL from Step 3 (or `https://newlookimpex.store` if you own it)
   - `SECRET_KEY`, `N8N_WEBHOOK_TOKEN` → auto-generated by Render
3. Deploy. First boot creates tables + admin user automatically. Check
   `https://<your-api>.onrender.com/api/health` → `{"status":"ok",...}`.
4. Log in once at `<your-api>/api/docs` if you like — or skip to the admin UI later.

## Step 3 — Vercel: frontend website (5 min)

1. Create a **free Vercel account** (Continue with GitHub) → **Add New → Project** →
   import `new-look-impex` → set **Root Directory** to `frontend` → Deploy.
2. Before/after deploy, set the env var (Project → Settings → Environment Variables):
   `NEXT_PUBLIC_API_URL=https://<your-api>.onrender.com` → **Redeploy** after adding it
   (the URL is baked in at build time).
3. Your site is live, e.g. `https://new-look-impex.vercel.app`.

## Step 4 — Connect the two + move your data (10 min)

1. Render dashboard → your API service → Environment → set
   `CORS_ORIGINS=https://<your-vercel-app>` (comma-separate if keeping localhost too) → Save
   (Render auto-redeploys).
2. On the **live** site, open `/admin/login` → log in with `ADMIN_EMAIL/ADMIN_PASSWORD`.
3. **Products:** Admin → Catalogue → **CSV Import** → *Download CSV template*, fill it in, then upload.
   You will see a **preview** of every row (validation errors, duplicate-`external_product_id`
   detection, create vs update) before anything is written. Choose a commit mode
   (*update existing + create new* / *create new only* / *update existing only*). Imported rows stay
   **draft** unless you tick *Publish imported rows*. A snapshot is saved next to this repo
   (`product-catalogue-export.csv`); export a fresh one anytime via Admin → Products → Export.
4. **Photos:** the 8 local images don't transfer automatically — re-upload each product's
   photos once via Admin → Products → Images (with rights source), or configure Supabase
   Storage first (Step 1.3 + `STORAGE_BACKEND=s3` + `S3_*` vars on Render) so all future
   uploads persist permanently.
5. **Google login (if used):** Google Cloud console → OAuth client → add a second
   Authorised redirect URI `https://<your-api>.onrender.com/api/auth/google/callback`
   and set the same value in Render's `GOOGLE_LOGIN_REDIRECT_URI` (+ client ID/secret,
   `GOOGLE_LOGIN_ENABLED=true`, `GOOGLE_ALLOWED_EMAILS`).
6. Optional: point your `newlookimpex.store` domain at Vercel (Vercel → Domains) and update
   `PUBLIC_SITE_URL` on Render — canonical URLs and sitemap follow automatically.

## Step 5 — Daily use (no code)

- **Update products / upload photos:** live site → `/admin/products`
- **Bulk product import:** `/admin/csv-import` (template → preview → commit modes)
- **New enquiries & leads:** `/admin/enquiries` (filter by country/status, search, internal notes, CSV export), plus `/admin/rfqs`, `/admin/buyers`
- **Business info, WhatsApp number, SEO defaults:** `/admin/settings` — the WhatsApp click-to-chat number, address, social links and default SEO title/description are all editable here (no code change needed)
- **Per-page SEO metadata:** `/admin/seo-pages`
- **Catalogue PDF, SEO, keywords, AI import:** same sidebar as local
- **Code updates:** edit locally → `git commit` → `git push` → Vercel/Render redeploy automatically.

## Troubleshooting
- Site shows but catalogue empty → you skipped Step 4.3 (import CSV) or products are drafts.
- API calls fail from the live site → `NEXT_PUBLIC_API_URL` wrong/stale (redeploy frontend after changing it); `CORS_ORIGINS` missing the Vercel URL.
- Images vanish after Render sleeps → expected on free local disk; configure Supabase Storage (Step 1.3) and re-upload.
- First visit slow (~50 s) → Render free cold start; subsequent pages are fast.
- Google sign-in `redirect_uri_mismatch` → the URI in Google Cloud must character-match
  `https://<your-api>.onrender.com/api/auth/google/callback`.
